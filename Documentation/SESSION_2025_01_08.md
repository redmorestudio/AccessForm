### 2. Fixed Y-Axis Drag Direction (CRITICAL FIX)
**File Modified:**
- `Pages/TagModificationModal.razor:1739`

**What Changed:**
```csharp
// OLD (WRONG):
draggedField.Y = originalFieldY - (deltaY / DPI_SCALE);

// NEW (CORRECT):
draggedField.Y = originalFieldY + (deltaY / DPI_SCALE);
```

**Why:**
- Syncfusion uses **TOP-LEFT** coordinates (Y=0 at top, Y increases downward)
- NOT standard PDF bottom-left coordinates
- Moving mouse down (positive deltaY) should **increase** Y, not decrease it
- See RADIO_BUTTON_IMPLEMENTATION.md lines 85-89 for coordinate system docs

### 3. Switched from V4 to V2 API (CRITICAL FIX)
**File Modified:**
- `Pages/Index.razor:1995-1998`

**What Changed:**
```csharp
// OLD:
formData.Add(new StringContent(fieldsJson), "fieldUpdates");
var response = await httpClient.PostAsync("/api/update-pdf-fields-v4", formData);

// NEW:
formData.Add(new StringContent(fieldsJson), "fields");  // V2 expects "fields" parameter
var response = await httpClient.PostAsync("/api/update-pdf-fields-v2", formData);
```

**Why:**
- V4 uses `PdfCompleteRebuildService` → calls `pdf_complete_rebuild.py` (PyMuPDF)
- **V4 DESTROYS TEXT CONTENT** - garbles text, creates overlapping characters
- V2 uses `PdfFieldTagEditorService` → just updates fields without destroying PDF
- V2 preserves all text content correctly

**API Comparison:**
- **V2:** `PdfFieldTagEditorService` - surgical field updates only
- **V3:** `ITextFieldRebuildService` - uses iText for field rebuild
- **V4:** `PdfCompleteRebuildService` - **BROKEN** - destroys text via Python script

## Outstanding Issues

### 1. PDF Accessibility Errors (NOT FIXED YET)

**Errors Found:**
- **9 "Path object not tagged" errors** on page 3
- **2 "Object missing in object reference" errors** on pages 1-2

**What These Mean:**
1. **Path objects not tagged:** Decorative path objects (lines, borders, table rules) are not marked as artifacts
   - Should be wrapped in `/Artifact BMC ... EMC` marked content
   - Required for PDF/UA compliance

2. **Object missing in object reference:** Incomplete PDF structure tree
   - Missing parent tree mappings
   - Structure elements not properly referenced

**Current State:**
- PassportPDF **will NOT fix these** (user confirmed)
- iText7 **might work** but uncertain
- PyMuPDF has **no high-level API** for artifact marking
- **May need manual external fixes** in Adobe Acrobat

**Manual Fix Process (External):**
```
1. Open PDF in Acrobat Pro
2. Open Content panel (right side)
3. Expand page with errors (Ctrl+click arrow)
4. Find path tags
5. Right-click → "Create Artifact"
6. Choose artifact type: "Page"
7. Click OK
```

**Potential Solutions to Investigate:**
- **Option A:** Create custom iText7 service to mark artifacts
  - Parse page content streams
  - Find path operations (m, l, c, re, etc.)
  - Wrap in /Artifact marked content
  - Rebuild content stream

- **Option B:** Extend PyMuPDF script with low-level API
  - Use `page.read_contents()` to get content stream
  - Manually insert `/Artifact BMC` and `EMC` operators
  - Use `doc.update_stream()` to write back
  - **Complex and error-prone**

- **Option C:** Accept manual fixes
  - Document the manual process
  - User fixes in Acrobat before final delivery

## Important Notes

### Coordinate Systems
- **Syncfusion:** Top-left origin (Y=0 at top, increases downward)
- **PDF Standard:** Bottom-left origin (Y=0 at bottom, increases upward)
- **We use:** Syncfusion coordinates directly, no conversion needed
- **Page dimensions:** 612x792 points (US Letter)

### DPI Scaling
- PDF points: 72 DPI
- Image rendering: 150 DPI
- Conversion factor: 150/72 = 2.08333
- Used for drag calculations: `deltaX / DPI_SCALE`
